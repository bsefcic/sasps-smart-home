# Instructions for contributors and coding agents

## Purpose and boundaries

This repository compares two functionally equivalent Java smart-home implementations. Read `docs/scope.md`, `docs/architecture.md`, and the issue before editing.

- Java 17+ (no preview features), Maven Wrapper 3.9.11, JUnit 5. Run from the repository root.
- Maven modules: shared/contracts, shared/simulators, implementations/baseline, implementations/patterns, app, acceptance-tests. Production code uses `src/main/java`; tests use `src/test/java` and `src/test/resources`.
- Public immutable DTOs and interfaces live in contracts; neutral vendor APIs live in simulators. No commands, scenes, policies, or orchestration in shared modules.
- Baseline and patterns must not depend on or import each other. Only app and acceptance-tests load both. Preserve equivalent fixtures, errors, workloads, and behavior.
- Do not introduce Spring, a database, Lombok, reflection-based DI, global mutable registries, or speculative patterns for this starter.
- Do not intentionally break, duplicate, or slow down baseline. Do not assume patterns win every metric.

## Workflow

1. Read CONTRIBUTING.md and the nearest implementation's AGENTS.md. State a short plan and inspect existing code.
2. Keep the change within the issue; document any needed contract decisions rather than silently inventing behavior.
3. Use clear packages, explicit dependencies, immutable records for snapshots/DTOs, and constructor injection for adapters/commands where appropriate. Avoid shared mutable state.
4. Add meaningful JUnit tests. Public behavior is verified by the common parameterized acceptance suite; variant-specific tests stay in their module. Do not weaken tests to hide differences.
5. Run `./mvnw spotless:apply` to format Java and `./mvnw clean verify` for compilation, tests, and format checks. On Windows use `.\mvnw.cmd` with the same goals.
6. Run `java -jar app/target/smart-home.jar baseline` and the patterns equivalent after packaging. Update affected docs and report exact checks and limitations in the PR.

The Maven compiler treats warnings as errors. `verify` checks Java formatting with Spotless. Maven Wrapper scripts are generated by Apache: do not rewrite them by hand. Do not commit target directories, credentials, generated experimental workspaces, or fabricated measurements. Do not merge PRs or change repository settings as part of a coding issue.

Controlled AI experiments use isolated workspaces and neutral instructions, not these architecture-specific development instructions. See docs/evaluation.md.
